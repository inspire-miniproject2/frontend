# MinwonON 프론트엔드 작업 로그

> 작업 기간: 2026-08-17 ~ 2026-08-18
> 기준 브랜치: `develop`
> 작업 브랜치: `feature/frontend-ui-mock`

## 1. 프로젝트 기반 구성

- React 19, TypeScript, Vite 기반 프론트엔드 프로젝트 구성
- `krds-react` 스타일과 컴포넌트 적용
- React Router를 이용한 화면별 라우트 구성
- 1024px 축소 환경을 고려한 반응형 스타일 구성
- 공통 전자정부 배너, 헤더, 주 메뉴, 본문, 푸터 레이아웃 구현

## 2. 디자인 시스템 및 공통 UI

- `FRONTEND_STRUCTURE.md`와 `MinwonON_Wireframe.pdf`를 바탕으로 `design-system.md` 작성
- KRDS 기반 색상, 타이포그래피, 간격, 상태, 접근성 규칙 정리
- 페이지 헤더, 피드백 배너, 폼 필드, 상태 배지, 단계 표시기, 페이지네이션 등 공통 컴포넌트 구현
- 한국어 예시 데이터와 로딩·오류·비활성·완료 상태 표현 기반 마련

## 3. 페이지 구현 및 구조 개선

- 로그인·회원가입 화면 구현
- 민원 작성·제출 전 확인·접수 완료 화면 구현
- 내 민원 목록·상세 화면 구현
- 공개 답변 목록·상세 화면 구현
- 공무원 업무함·민원 처리 화면 구현
- 관리자 민원처리 현황 화면 구현
- 알림 및 404 화면 구현
- 단일 `Screens.tsx`를 제거하고 도메인별 폴더와 페이지별 파일로 분리
- 반복되는 폼 입력과 민원 목록 요소를 페이지 공통 컴포넌트로 분리

## 4. 민원 신청 Mock API

- MSW 기반 브라우저 Mock 환경 구성
- `GET /api/v1/complaint-categories` Mock 핸들러 구현
- `POST /api/v1/complaints` multipart Mock 핸들러 구현
- API 명세에 따른 제목·본문·카테고리·알림 채널 검증 구현
- 자동 배정 성공 `ASSIGNED`와 배정 대기 `RECEIVED` 응답 구현
- 실제 API와 Mock이 같은 API 클라이언트와 계약 타입을 사용하도록 분리
- `VITE_ENABLE_MOCKS=false` 설정으로 실제 API 전환이 가능하도록 구성
- 민원 작성값과 첨부파일은 브라우저 저장소가 아닌 React 메모리에만 보관

## 5. 민원 신청 화면 연동

- 민원 작성 화면에서 카테고리 Mock API 조회
- 작성값·첨부파일·이메일 알림 선택을 메모리 상태에 저장
- 제출 전 확인 화면에서 입력 내용을 읽기 전용으로 표시
- 확인 체크, 제출 중 비활성화, 중복 제출 방지 처리
- 접수 완료 화면에서 접수번호, 접수 시각, 배정 결과와 현재 상태 표시
- 작성 상태 또는 제출 결과 없이 직접 접근할 경우 작성 화면으로 복귀

## 6. 검증 결과

- `pnpm typecheck` 통과
- `pnpm build` 통과
- 주요 화면 라우트의 개발 서버 HTTP 200 응답 확인
- Mock 기능은 개발 환경에서만 활성화되고 프로덕션 빌드에서는 시작되지 않도록 구성

## 7. 후속 작업

- 실제 API 개발 완료 후 `VITE_ENABLE_MOCKS=false` 및 API Base URL 설정
- 인증 토큰 연결과 서버 오류 코드별 사용자 메시지 보강
- Mock 핸들러 단위 테스트 및 민원 신청 흐름 E2E 테스트 추가
- 실제 서버 파일 제한값 확정 후 첨부파일 검증 적용
